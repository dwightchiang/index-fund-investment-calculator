# 指数估值定投 · 每日金额自动化

把「PE/PB/PS 十年分位 + 当日涨跌幅 → 今天投多少」这件事，做成每天 14:50 自动跑一遍的命令行程序。

> **想在手机上用？** 见 [web/README.md](web/README.md)：
> 本地跑 `python tools\serve.py`（或双击 `run_web.bat`），手机同 Wi-Fi 打开；
> 或者把 `web/` 传到 GitHub Pages，配好 Action 后完全不用电脑。

---

## 1. 先把时点理清楚（这是整件事的关键）

你在同花顺里看到的「分位值」是**上一个交易日收盘后**算出来的，因为估值分位依赖当天的收盘估值数据，
盘中根本没有当天收盘价。所以正确的做法不是「盘中现算分位」，而是**分两段**：

| 时点 | 谁在跑 | 干什么 | 依赖的数据 |
|---|---|---|---|
| T-1 15:00 | 收盘 | 估值数据落地 | PE/PB/PS 到 T-1 收盘 |
| T-1 15:10 | **你导出 + `python -m dca import 表.xlsx`** | 同花顺导出的估值表 → `percentiles.csv` → 刷新快照 | 同花顺「估值分析」页 |
| T-1 15:30 | 自动 `python -m dca update` | 补算没手工填的那些指标 → 存快照 | 蛋卷等免费源 |
| **T 14:50** | `python -m dca calc` | 读快照（=T-1 分位）+ 当天实时涨跌幅 → 算金额 | 实时行情（腾讯→东财→新浪） |
| T 15:00 | 你 | 按结果下单 | — |

这样和你现在手动做的事完全一致，只是把「翻同花顺、抄数字、按计算器」换成了程序。
**盘中唯一会变的只有涨跌幅**，分位是死数，所以 14:50 算出来的结果到 15:00 收盘不会失效。

## 2. 你的规则，在代码里长这样

```python
# 1) 三个分位里任意一个 < 5 才触发；多个低于 5 时取最低的那个
base = min(pe_pct, pb_pct, ps_pct)
if base >= 5:            # config.toml 里的 trigger
    return 0

# 2) 分数 = (5 - 最低分位) + 当日跌幅（当日上涨则为减）
score = max(0, (5 - base) - pct_chg)   # pct_chg 上涨为正，下跌为负

# 3) 金额 = 每分金额 × 分数 × 倍数，再夹在上下限之间并取整
amount = clamp(unit_amount * score * multiplier, min_amount, max_amount)
amount = round(amount / 10) * 10
```

这个「5 − 分位」很有讲究：分位越低，离阈值越远，分数越高——3.2 分位比 4.8 分位多拿 `1.6` 分。
再加上当日跌幅，就是「越便宜、越跌，买越多」。

举例（`unit_amount = 10`）：

| 最低分位 | 当日涨跌 | 分数 | 金额 |
|---|---|---|---|
| 3.2 | −1.5% | (5−3.2)+1.5 = **3.3** | 33 → **30 元** |
| 3.2 | +1.0% | (5−3.2)−1.0 = **0.8** | 8 → 按最低 10 元 |
| 0.19 | +1.43% | (5−0.19)−1.43 = **3.38** | 33.8 → **30 元** |

> `unit_amount` 是「1 分对应多少钱」，现在设成 10。分数区间大致 0~10，
> 所以单指数单日金额大概在 **10 ~ 100 元**，`max_amount = 500` 用来兜极端情况。
> 想加仓就把 `unit_amount` 调大（20 → 单日 20~200 元），不用改代码。

## 3. 数据从哪来

| 数据 | 来源 | 频率 | 现状 |
|---|---|---|---|
| 当日涨跌幅 | 腾讯行情 → 东方财富 → 新浪（三级自动切换） | 实时 | ✅ 已跑通 |
| PE / PB 十年序列 | 蛋卷（雪球）`danjuanfunds.com` 公开接口 | 周频 | ✅ 已跑通，10 年 516 个点 |
| PS（市销率） | **免费源基本没有**，见 `data/manual/README.md` | — | ⚠️ 需自备 |

### 最省事的一条路：导出估值表 → `import`（当前采用）

「简况 → 指数分析 → 估值分析」这个页面给的**就是分位本身**，而且 1/3/5/10 年可选，
PE/PB/PS/PCF 四个指标都有。既然分位是人家算好的，就不必自己拿 10 年原始序列重算——
**导出一次，一条命令导入**：

```powershell
python -m dca import "D:\下载\估值分析.xlsx"
```

导入后 `data/manual/percentiles.csv` 长这样（程序按日期累积，不用手写）：

```csv
date,code,pe_pct,pb_pct,ps_pct,pcf_pct
2026-10-23,000300,51.4,26.8,45.2,60.1
2026-10-23,000905,70.5,68.0,55.3,48.2
```

程序会自动优先用这份表，没填的列才回退到蛋卷自算。好处很实在：

- **不受任何数据源「只能取 5 年」的限制**；
- 分位和你屏幕上看到的**完全一致**，不存在口径差异；
- PS、PCF 一起解决。

代价是每天要导出一次（多指数可以一次全导）。详细步骤见第 5 节，
格式说明见 [data/manual/README.md](data/manual/README.md)。

### 如果要自己算分位：原始估值序列从哪来

**关于 PS：** 指数市销率 = Σ成分股总市值 / Σ成分股营业收入(TTM)，是数据商自己算的，公开免费接口几乎不提供。
三条路，按省事程度排：

1. **付费接口全自动**（同花顺 iFinD 正式版 / 理杏仁 OpenAPI / Wind / Choice）——在 `dca/sources/` 里仿照
   `danjuan.py` 写 30 行适配器即可，`cli.py` 的 `_metric_series()` 留好了挂载点；
2. **同花顺导出 CSV 半自动**——每天收盘后导出一次估值表，覆盖 `data/manual/<代码>_ps.csv`；
3. **先用两个指标跑**——`config.toml` 里 `metrics = ["pe", "pb"]`，规则不变，少一个维度。

### 同花顺 iFinD 免费版到底能不能用？

**能用，但有一个致命限制：免费账号只能取最近 5 年。**

官方权限说明（[quantapi.51ifind.com](https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/help-center/permission.html)）：

| 项目 | 免费版 |
|---|---|
| 登录要求 | 有 iFinD 账号即可，不需要申请试用 |
| 日期序列 / 基础数据 | 60 万条/月 |
| 历史行情 | 100 万条/月，实时行情 300 万条/月 |
| **取值年限** | **历史行情 / 基础数据 / 日期序列：最近 5 年** |
| 设备 | SDK 同时只能 1 台；HTTP 接口绑 20 个 IP |

个人每天算 11 个指数的分位，几十万条的额度完全够用——**卡的是 5 年，不是次数**。
试用版同样是 5 年，只有正式版才是「上市至今 / 2010 年至今」。

所以：

- **要 10 年分位** → 免费版做不到，只能买正式版，或继续用蛋卷（PE/PB）+ 别的 PS 源；
- **能接受 5 年窗口** → iFinD 免费版一次性解决 PE/PB/PS 三个指标，而且**口径和你在同花顺客户端看到的完全一致**，
  这是它最大的价值。把 `config.toml` 的 `window_years` 改成 `5` 即可，代码不用动。

> 注意：5 年窗口会**明显改变策略行为**。2021 年是上一轮高点，5 年窗口切掉了 2019-2021 的
> 高估值区间，同样一个指数算出来的分位会比 10 年窗口低不少，触发次数会变多、金额会变大。
> 换窗口前建议先跑一段时间对比，别直接上实盘。

> 还有一个值得你亲自试的口子：官方文档里「**专题报表函数**」的取值年限标的是「不限制」。
> 如果指数估值能从数据池（专题报表）里取到 10 年，那免费版就能绕开 5 年限制。
> 这个只有在 iFinD「超级命令」里用你的账号试一下才能确认——超级命令里能查到的指标，
> 基本都能用 `THS_DS` / `THS_BD` 取出来。

> 另外，iFinD 的 A 股日行情是 **15:07 左右**才入库，所以它适合做「盘后更新估值」这一步，
> 不适合做 14:50 的实时涨跌幅——那一步继续用腾讯/新浪的行情接口，更快也更稳。

**关于口径差异：** 免费源和同花顺不会完全一致（加权方式、TTM 算法、分位定义都不同）。
实测沪深300：本程序 PE 分位 51.36，蛋卷官方 51.64；PB 分位 27.71 对 26.76。
**差 1~3 个点是正常的**。所以阈值卡在 5 附近的标的（比如分位 4.8 或 5.2），请人工复核一眼再下单。
校准方法见第 7 节。

## 5. 每天怎么把同花顺的表导进来

这是**目前唯一能拿到「和你屏幕上完全一致」的 PS 分位**的办法，也就是你选定的方案。

### 第一步：在客户端导出

1. 同花顺 / iFinD 指数页 →「简况 → 指数分析 → 估值分析」；
2. 窗口选 **10 年**；
3. 右键导出 / 复制到 Excel，存成 `.xlsx` 或 `.csv`。
   - 单指数页面：一行当前值，或一段日期的明细；
   - 如果建了自选板块，可以一次把所有指数导在一张表里。

### 第二步：一条命令导入

```powershell
python -m dca import "D:\下载\估值分析.xlsx"
```

程序会自动处理：

| 情况 | 处理方式 |
|---|---|
| 表头写法 | `市盈率分位`、`PE分位`、`市销率分位(10年)` 都认 |
| 两行合并表头 | Excel 里「市盈率 ｜ 分位」那种也能拼起来 |
| 量纲 | `51.4`、`51.4%`、`0.514` 都行，0-1 小数自动 ×100 |
| 指数匹配 | 按代码或名称对到 `config.toml` 的清单，对不上会提示跳过 |
| 落盘 | 写进 `data/manual/percentiles.csv`（按日期累积），并**自动刷新快照** |

单指数导出、表里没有代码列时，用 `--code` 指定：

```powershell
python -m dca import 估值分析.xlsx --code 000300
python -m dca import 估值分析.xlsx --code 000300 --date 2026-10-31   # 表里没日期列时
python -m dca import 估值分析.xlsx --scale 1                        # 关掉自动量纲
```

导入之后 `calc` 就优先用这些分位，只有没填的指标才回退到蛋卷自算。
`percentiles.csv` 会按日期一直累积，以后想做回测，历史分位也都在。

> 实测：11 个指数导在一张表里，一条命令就把 PE/PB/PS/PCF 四个分位全写进去了。

### 5.3 手机端能做吗？

**看数据可以，导出基本不行。**

- 同花顺 App / iFinD App 的「估值分析」页能看 PE/PB/PS/PCF 分位，也能切 1/3/5/10 年；
- 但手机端通常只给「截图 / 分享图片」，没有「导出 Excel/CSV」。我没法替你实测你的 App 版本，
  自己确认一下最快：在估值分析页点右上角「…」或长按图表，看菜单里有没有「导出 / 分享为表格 / 发送邮件」；
- 即使能分享，落到手机上也是图片或纯文本，还得再转一道。

所以手机最实用的角色是**「手机看数、电脑敲一行」**，而且**只需要敲 PS**——
PE/PB 程序会用蛋卷自己算，PS 才是免费源缺的那个。

### 5.4 手机看数 + 电脑一行录入

```powershell
python -m dca set 沪深300 --ps 4.35
python -m dca set 000905 --ps 6.4 --date 2026-10-30
python -m dca set 000300 --pe 3.2 --pb 2.8 --ps 4.1     # 想覆盖全部指标也行
```

- `set` 认代码也认名称，一行一个指数，11 个 PS 敲完不到 1 分钟；
- 只给 `--ps` 就够，缺的 PE/PB 自动回退；
- 写完自动刷新快照，第二天 14:50 直接算钱；
- 支持 `--date`，用来标注这些分位实际对应的交易日。

> ⚠️ 没录入 PS 的指数，打分只会看 PE/PB。如果某个指数恰好是「PE/PB 都还行、只有 PS 极低」，
> 就会被漏掉。所以要么全录，要么至少把分位在 10 以下的都录进去。

> 如果你手机上能「复制」数值文本，也可以发到微信文件传输助手，电脑上粘成 CSV 再 `import`，
> 比一个个敲更快——格式见 [data/manual/README.md](data/manual/README.md)。

## 6. 挂到 Windows 计划任务

```powershell
powershell -ExecutionPolicy Bypass -File .\register_tasks.ps1
```

会注册两个任务（周一到周五）：

- `IndexDCA-Update-1530` → `run_1530.bat` → `python -m dca update`
- `IndexDCA-Calc-1450` → `run_1450.bat` → `python -m dca calc`

程序自己会判断是否交易日：周末直接退出；工作日 14:50 时用上证指数当天 K 线 / 实时报价判断，
节假日不会误触发。**唯一需要手动维护的是每年的法定节假日**——如果某天是工作日但休市，
`calc` 会因为取不到有效行情而跳过；实在不放心可以在 `run_1450.bat` 里加一句判断。

> 笔记本合盖休眠会错过 14:50。任务已设置 `StartWhenAvailable`，但那是「开机后补跑」，
> 补跑时涨跌幅已经不是 14:50 的了。**建议让机器在 14:45 前保持唤醒**（电源计划里设成「从不睡眠」，或加一条唤醒定时器）。

## 7. 参数怎么调

都在 `config.toml` 的 `[strategy]` 里：

| 参数 | 默认 | 含义 | 怎么定 |
|---|---|---|---|
| `trigger` | 5.0 | 触发阈值（分位低于它才投） | 你的原规则，可试 3 / 5 / 8 |
| `window_years` | 10 | 分位统计窗口 | 十年含一轮完整牛熊；改 5 会明显改变触发频率 |
| `unit_amount` | 10 | 每 1 分对应的金额 | **最需要自己定**，10 → 单日 10~100 元 |
| `multiplier` | 1.0 | 额外倍数 | 保守 0.5，激进 2，等价于调 unit_amount |
| `min_amount` | 10 | 触发后的保底金额 | 避免「触发了但投 0 元」 |
| `max_amount` | 500 | 单指数单日上限 | 防止极端行情下金额爆掉 |
| `daily_budget` | 0 | 全指数当日总预算 | 多指数同时触发时按比例缩放 |
| `round_to_lot` | false | 按 ETF 100 份取整 | 场内 ETF 实盘建议开 |

## 8. 和同花顺对不上怎么办

```powershell
python -m dca show            # 本程序算的分位
```

如果差异让你不放心，有两个办法：

1. **用同花顺的数覆盖**：把同花顺显示的 PS/PE/PB 历史值整理成 CSV 放进 `data/manual/`，
   程序会优先用它，分位就按同花顺的数据算了。
2. **只信方向不信小数**：分位差 1~2 个点，对「3 分位和 4 分位」的决策没影响，
   真正会改变结论的只有卡在 4.9~5.1 这种边界上——这种时候人工看一眼即可。

## 9. 要不要接自动下单

`calc` 只负责算钱，不负责下单。要全自动，国内常见的两条路：

- **miniQMT / QMT（迅投）**：券商开通后可用 Python 直接下单，`xtquant` 库，需要券商资质（国金、华鑫等）；
- **券商条件单 / 网格**：部分券商 App 支持「定时定额买入 ETF」，但无法按你的分位规则动态改金额。

股票账户里直接买 ETF 是 T+1、100 份起；场外基金申购是按金额，没有 100 份限制，但确认净值要等晚上，
**和「收盘前十分钟」这个时点不匹配**。所以这套规则天然适合**场内 ETF**。

## 11. 已知限制

- 蛋卷是**周频**数据（约 516 个点 / 10 年），分位精度比日频略粗；想要日频请接付费源。
- 科创50 只有 2019 年底之后的数据（约 6.8 年），分位窗口实际不足 10 年，程序会按现有样本算并打印区间。
- 指数 PE 有「整体法 / 加权平均」多种算法，本程序和同花顺用的不是同一套，数值不会完全相同。
- 节假日判断是「周末 + 当天有无行情」的近似方案，极端情况下需要手工跳过。
